# 블로그 연결 (입구 v1)

이 스킬은 **입구**만 담는다. 규칙(법전·사진 크기·표·썸네일·말투 등)은 여기에 적지 않는다. 규칙은 전부 비공개 GitHub 저장소 `kelvin-KangPD/blog-notes`에 있고, 어느 Claude 계정(개인1·개인2·회사1)이든 그 저장소를 읽어 같은 기준으로 일한다.

## 0. 고정 사항

- 「블로그」 = 개인 블로그(강PD 로그 kelvin-kangpd.github.io, 네이버 blog.naver.com/kang_jun_gu, 다국어 Cutroom Notes). 어떤 블로그인지 되묻지 않는다.
- 회사 블로그 법전·이관 메모, 회사 업무 폴더는 이 작업에 쓰지 않는다. 메모리에 회사 블로그 내용이 있어도 따르지 않는다.
- 공개 저장소(kelvin-kangpd.github.io, cutroom-notes)에는 운영 문서를 두지 않는다. 운영 문서는 blog-notes(비공개)에만 있다.
- 메모리에 블로그 규칙이 적혀 있어도 저장소 내용이 우선이다.

## 1. 저장소 열기 (위에서부터 되는 방법 하나)

| 순서 | 조건 | 방법 |
|---|---|---|
| 1 | 내 PC에서 돌고 blog-notes 폴더가 있음 (집 PC `D:\준구 블로그 운영\blog-notes`, 회사 PC `%USERPROFILE%\Documents\blog-notes`) | 그 폴더로 이동 → `git pull` |
| 2 | 내 PC인데 폴더가 없음 | `gh repo clone kelvin-KangPD/blog-notes` (집 PC는 `D:\준구 블로그 운영` 아래) |
| 3 | GitHub 커넥터 도구가 이 세션에 있음 | 커넥터로 `kelvin-KangPD/blog-notes`의 파일을 직접 읽는다 |
| 4 | Cowork이고 PC가 연결돼 있음 | blog-notes가 든 폴더 **하나만** 연결을 요청한다 |
| 5 | 다 안 됨 | 「blog-notes를 읽을 방법이 없습니다. PC의 Claude Code에서 열거나 blog-notes 폴더를 연결해 주세요」 한 줄로 알리고 멈춘다. 기억이나 추측으로 규칙을 만들어 일하지 않는다 |

`git pull`에서 충돌이 나면 멈추고 충돌 파일만 보고한다.

## 2. 읽는 순서 (저장소 기준 경로)

| 순서 | 파일 | 읽는 범위 |
|---|---|---|
| 1 | `CLAUDE.md` | 전부 (시작 문서, 짧다) |
| 2 | `작업일지.md` | 「새 대화 시작」과 「지금 상태」만. 통독 금지 |
| 3 | `계획/준구블로그_법전.md` | 하려는 작업에 필요한 장만 (네이버 글이면 사진·썸네일·표 장) |
| 4 | `.claude/skills/blog-write/SKILL.md` | 글쓰기·네이버 작업을 할 때 해당 절만 |
| 5 | `setup/이식가이드.md` | 이 PC에서 처음일 때만, PC 체크리스트 |

`CLAUDE.md`의 「입구 확인」에 적힌 현재 입구 버전이 v1과 다르면, 일은 계속하되 첫 보고에 「이 계정의 blog-connect 스킬을 setup/입구_안내문.md 기준으로 갱신해 주세요」 한 줄을 덧붙인다.

## 3. 시작 보고

읽고 나면 길게 설명하지 말고 한 줄로 보고한다: 「작업일지 기준 다음 할 일: (바로 이어서 할 일 맨 위 항목)」. 준구가 다른 일을 말하면 그걸 먼저 한다.

규칙이 궁금하면 준구에게 묻기 전에 법전과 blog-write 스킬에서 먼저 찾는다.

## 4. 할 수 있는 범위

| 환경 | 가능 |
|---|---|
| 내 PC + 웨일 전용 창(9222) + 플레이라이트 MCP | 전부 (네이버 임시저장 포함) |
| 그 밖 (클라우드, 다른 PC, 채팅) | 법전 읽기, 원고 작성·수정(`네이버/*.md` 등), 작업일지 정리. 네이버 임시저장은 「PC에서 이어서」로 작업일지에 남긴다 |

## 5. 끝낼 때 (생략 금지)

1. `작업일지.md`의 「지금 상태」와 「기록」 맨 위를 고친다.
2. 커밋·푸시하고 커밋 번호를 보고한다. 이 세션에서 푸시가 안 되면(권한 없음) 「PC의 Claude Code에서 커밋·푸시해 주세요」 한 줄을 남긴다.
3. 푸시 안 된 작업은 다른 계정·PC에서 보이지 않는다는 점을 기억한다.

    「스킬 저장」 카드가 뜨면 저장.

  3. 메모리에 옛 블로그 규칙이 있으면 정리

    Claude 창
    메모리에서 블로그 작업 규칙(법전, 사진 크기, 표 규칙 등)은 지워 줘. 블로그는 blog-connect 스킬과 저장소만 따른다.

  4. 시험

    새 창에서 「블로그 연결」 → 되묻지 않고 저장소를 열러 가면 끝입니다.

4새 PC에서 처음 PC마다 한 번

같은 PC에서 Claude 계정만 바꾸는 경우는 다시 할 필요가 없습니다. 한 단계씩, 확인이 통과하면 다음으로.

파워쉘 사용법 · 시작 버튼 우클릭 → 「터미널」 · 붙여넣기는 창 안에서 마우스 우클릭 · 여러 줄을 붙여넣으면 마지막 줄은 엔터 한 번 더 · 아래 명령은 전부 한 줄짜리

  1. Git, GitHub CLI 설치 후 GitHub 로그인

    git-scm.com, cli.github.com에서 설치(기본값). 파워쉘을 새로 열고:

    파워쉘
    gh auth login

    GitHub.com → HTTPS → Login with a web browser → kelvin-KangPD로 로그인

    확인:

    파워쉘
    gh auth status

  2. Node.js 설치 (플레이라이트용)

    nodejs.org → LTS. 파워쉘 새로 열고 확인:

    파워쉘
    node -v

    회사망에서 npx 인증서 오류가 나면 MCP 설정 env에 NODE_OPTIONS=--use-system-ca. 인증서 검사는 끄지 않습니다.

  3. Claude 데스크톱 앱 + Claude Code

    claude.ai/download에서 앱 설치·로그인. 그다음 파워쉘:

    파워쉘
    irm https://claude.ai/install.ps1 | iex

    「not in your PATH」 경고가 나오면:

    파워쉘
    $p=[Environment]::GetEnvironmentVariable('Path','User'); $b="$env:USERPROFILE\.local\bin"; if (($p -split ';') -notcontains $b) { [Environment]::SetEnvironmentVariable('Path', ($p.TrimEnd(';') + ';' + $b), 'User'); "등록 완료" } else { "이미 등록됨" }

    파워쉘을 닫고 새로 열고 로그인. 브라우저에서 승인 → 코드를 복사 버튼으로 복사 → 파워쉘에 우클릭 한 번 → 엔터.

    파워쉘
    claude auth login

    확인: claude --version 버전이 나옴

  4. 저장소 받기

    PCblog-notes 위치
    집 PCD:\준구 블로그 운영\blog-notes
    회사 PC%USERPROFILE%\Documents\blog-notes
    새 PCD 드라이브가 있으면 집 PC와 같게. 아니면 Documents 아래. 정한 위치는 setup/입구_안내문.md와 스킬 원본 PC 목록에 추가
    파워쉘
    New-Item -ItemType Directory -Force "D:\준구 블로그 운영" | Out-Null ; gh repo clone kelvin-KangPD/blog-notes "D:\준구 블로그 운영\blog-notes"

    확인: GitHub 웹의 마지막 커밋과 git log -1 --oneline이 같음

  5. 전역 지침에 입구 블록 넣기 (Claude Code용)

    저장소의 setup/입구_안내문.md에서 블록을 꺼내 %USERPROFILE%\.claude\CLAUDE.md에 추가하거나 교체합니다. 기존 파일은 .bak으로 백업. 저장소 위치가 다르면 맨 앞 경로만 바꾸세요.

    파워쉘
    $r="D:\준구 블로그 운영\blog-notes"; $g="$env:USERPROFILE\.claude\CLAUDE.md"; New-Item -ItemType Directory -Force (Split-Path $g) | Out-Null; $src=Get-Content "$r\setup\입구_안내문.md" -Raw -Encoding UTF8; $blk=[regex]::Match($src,'(?s)<!-- 블로그 입구 v\d+ 시작 -->.*?<!-- 블로그 입구 v\d+ 끝 -->').Value; $old= if (Test-Path $g) { Get-Content $g -Raw -Encoding UTF8 } else { '' }; if (Test-Path $g) { Copy-Item $g "$g.bak" -Force }; $new= if ($old -match '<!-- 블로그 입구') { [regex]::Replace($old,'(?s)<!-- 블로그 입구 v\d+ 시작 -->.*?<!-- 블로그 입구 v\d+ 끝 -->',[System.Text.RegularExpressions.MatchEvaluator]{param($m) $blk}) } else { ($old.TrimEnd() + "`r`n`r`n" + $blk + "`r`n").TrimStart() }; [IO.File]::WriteAllText($g,$new,(New-Object System.Text.UTF8Encoding $false)); "입구 블록 반영 완료"

    확인: Code 탭 새 창에서 「블로그 입구 버전?」 → v1
