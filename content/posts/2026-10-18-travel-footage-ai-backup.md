카메라 네 대로 찍은 탄자니아 여행 영상을 AI에게 맡겨 백업하고 검증한 다음,
**촬영 시각을 맞춰 프리미어 날짜별 시퀀스 16개까지 만들었다.**

손으로 했으면 주말 몇 번은 날렸을 일이다.
나는 외장하드를 꽂고 자고, 아침에 보고서를 확인했다.
작업은 수요일 밤에 시작해서 일요일에 프리미어 시퀀스까지 갔다. 그 과정을 최대한 자세히 남겨둔다. 다음 여행 때 내가 다시 볼 거라서.

## 출발점: 흩어진 파일과 꽉 찬 하드

여행에서 돌아오니 영상이 장비마다 흩어져 있었다.

| 위치 | 들어 있던 것 |
|---|---|
| 오즈모 나노 SD카드 | 여행 후반 영상 |
| 오즈모 나노 본체 메모리 | SD카드로 안 넘어간 영상 |
| 고프로 SD카드 | 여행 후반 영상 |
| 1TB 외장하드 | 여행 중에 옮겨둔 DAY 1~12. 남은 공간 6GB 남짓 |
| 2TB 외장하드 | 결혼식 사진 같은 예전 자료 320GB 정도 |
| 다른 노트북 | DAY 4·6 약 300GB |

카메라는 네 종류였다. 오즈모 나노, 고프로, 캐논, 그리고 소니 디카가 한두 개 섞여 있었다.

문제는 다음 날 또 촬영이 있어서 SD카드를 그날 밤 비워야 했다는 것.
원래 계획은 단순했다. 여행 자료를 전부 2TB 하드로 모으고, 2TB에 있던 예전 자료는 1TB로 옮기기.

AI가 여기서 순서 문제를 먼저 짚었다.
1TB에 6GB밖에 안 남았으니 320GB를 바로 옮기면 안 들어간다는 것, 그리고 SD카드까지 비우면 여행 파일이 2TB 하드 한 곳에만 남는다는 것.
그래서 계획을 이렇게 바꿨다.

| 파일 | 모을 곳 | 두 번째 사본 |
|---|---|---|
| 1TB 하드의 DAY 1~12 | 2TB 하드 | 1TB 하드에 당분간 그대로 둠 |
| 오즈모·고프로 SD, 오즈모 본체 | 2TB 하드 | 본체 D 드라이브 |
| 2TB 하드의 예전 자료 | 본체 D 드라이브로 이동 | |

헷갈리지 않게 외장하드에 이름도 붙였다. 2TB는 아내 이름, 1TB는 내 이름을 붙여서 부르기로 했다.

## 밤새 돌린 복사와 검증

Claude 데스크톱 앱으로 집 PC를 연결해서 맡겼다. AI가 파일 탐색, 복사, 비교를 직접 한다.
대량 복사는 명령어로 하면 느려서, 7-Zip 파일관리자를 화면 조작으로 띄워서 돌렸다.

처음엔 하나 끝나면 다음 걸 묻는 식이라 느렸다.
하나씩 할 이유가 있냐고 물었더니, 없었다고 하더라. 그다음부터 동시에 걸었다.

자기 직전 상태는 이랬다.

| 작업 | 진행 | 예상 완료 |
|---|---|---|
| 오즈모 본체 → 2TB 하드, D 드라이브 | 43개 중 일부 | 새벽 1시 반 |
| 2TB 하드 예전 자료 → D 드라이브 | 257GB 중 32GB | 새벽 3시, 검증 후 원본 삭제 |
| 1TB 하드 DAY 1~12 → 2TB 하드 | 908GB 중 125GB | 새벽 5~6시 |

자기 전에 지켜야 할 것도 정리해줬다. 오즈모 연결 그대로, 외장하드 두 개 그대로, Claude 앱과 7-Zip 창 닫지 않기.
아침 6시 20분쯤 보고를 남겨두겠다고 했고, 실제로 남아 있었다.

| 작업 | 아침 보고 |
|---|---|
| 오즈모 SD (66개, 103GB) | 2TB 하드와 D 드라이브 두 곳에 복사, 원본과 일치 |
| 고프로 SD (19개, 12GB) | 위와 동일 |
| 오즈모 본체 메모리 (22개) | 위와 동일 |
| 1TB 하드 DAY 1~12 → 2TB 하드 | 2,511개 전부 이름·크기 일치. 큰 파일 전부와 무작위 샘플을 합쳐 299개는 내용까지 비교 |
| 2TB 하드 예전 자료 → D 드라이브 | 9,938개 일치 확인 후 하드 쪽 삭제 |
| DAY 8과 DAY 10-11에 겹친 고프로 33개(17.5GB) | 같은 파일인 걸 확인하고 DAY 10-11 쪽 삭제 |

**검증이 끝난 것만 「지워도 됨」으로 적혀 있었다.**
SD카드 두 장과 오즈모 본체 메모리는 컴퓨터에서 지우지 말고 카메라에서 포맷하라고 해서 그렇게 하고 출근했다.

정리가 끝난 뒤 2TB 하드는 여행 전용이 됐다. DAY 1~15가 다 들어가고 794GB가 남았다.
이중 백업까지는 안 해도 되겠다 싶어서, 1TB 하드의 여행 사본은 결국 비우고 다른 자료를 넣는 데 쓰기로 했다.

## 촬영 시각 맞추기: 카메라마다 시계가 다 달랐다

편집하려면 네 대의 영상을 실제 찍은 순서대로 놓아야 한다.
그런데 카메라마다 시계 기준이 달랐다. 현지는 한국보다 6시간 늦은 UTC+3이다.

AI가 905개 파일의 촬영 시각을 전부 뽑아서 카메라별로 따져봤다.

| 카메라 | 시계 상태 | 맞춘 방법 |
|---|---|---|
| 오즈모 (412개) | 파일명에 한국 시간이 그대로 찍힘 | 파일명 시각에서 9시간 빼서 세계 표준시로, 다시 3시간 더해 현지 시각 |
| 고프로 (215개) | 엉망 | 아래에 따로 |
| 캐논 (276개) | 현지 시간이 아님 | 세계 표준시로 가정하고 +3시간, 아직 검증 전 |
| 기타 (2개) | 소니 디카 파일 등 | 따로 트랙 |

### 고프로

고프로는 켤 때마다 시간을 설정하라고 해서, 귀찮아서 대충 넣고 찍은 게 꽤 있다. 2016년 같은 엉뚱한 해로 넣은 것도 있을 거다.
그래서 파일에 적힌 시각은 믿을 수가 없었다.

AI가 찾은 실마리는 고프로가 영상 안에 같이 기록하는 GPS 데이터였다. GPS에는 위성에서 받은 정확한 시각이 들어 있다.
GPS가 잡힌 파일은 그 시각을 그대로 쓰고, 안 잡힌 파일은 시계가 일정하게 틀어져 있다는 점을 이용했다.
같은 시계 설정으로 찍힌 파일 번호 구간을 찾아서, 구간마다 얼마나 틀어졌는지 계산해 한꺼번에 되돌렸다.

| 파일 번호 구간 | 시계가 틀어진 정도 |
|---|---|
| 0418~0433 | 거의 정확 |
| 0434~0460 | 약 하루 |
| 0461~0479 | 약 3시간 20분, 반대 방향 |
| 0482~0636 | 약 153일 |
| 0637~0640 | 약 163일 |

이렇게 215개 중 214개를 복구했다. 나머지 하나(GX010479)는 이름에 「시각추정」을 붙여 표시해뒀다.
오즈모와 동시에 찍은 구간은 소리 파형을 비교해서 확인했는데, 10~20초 안쪽으로 맞았다.

### 캐논

캐논은 처음에 한국 시간이라고 봤다가, 다음엔 현지 시간이라고 가정하고 소리 비교를 두 번 돌렸는데 둘 다 헛수고였다.
결국 사진 한 장으로 풀렸다. 같은 시각에 오즈모는 낮인데 캐논은 저녁 먹는 장면이었다.
현지 시간이 아니라는 건 확실해졌고, 세계 표준시일 가능성이 커서 일단 +3시간으로 넣었다. 맞는지는 프리미어에서 내가 직접 보기로 했다.

먼저 DAY 1 하나로 시험해보고, 방식을 확인한 다음 전체를 한 번에 만들었다.

## 비용과 효율

이번에 처음 제대로 신경 쓴 게 사용량이다.
AI는 명령을 한 번 보낼 때마다 그때까지의 대화 전체를 다시 읽는다. 그래서 대화가 길어질수록 같은 작업도 몇 배 비싸진다.
20분 기다리는 건 거의 안 들고, 왔다 갔다 하는 횟수가 많이 든다.

중간에 지금 방식이 효율적이었냐고 물어봤다. 반반이었다는 답이 왔다.

| 작업 | 평가 |
|---|---|
| 고프로 시간 복구 | 스크립트 두세 번으로 수십 개를 한 번에 맞췄고 검증도 한 번에 통과 |
| 프로젝트 저장 위치 정리 | 몇 번 만에 끝 |
| 캐논 시간 확인 | 비효율. 외장하드 전체에서 소리를 뽑으려다 속도 때문에 포기했고, 26만 자짜리 에러 로그를 그대로 받았고, 가정을 검증 없이 믿고 소리 비교를 두 번 돌림. 사진 한 장이면 바로 알 수 있었음 |

그래서 마지막엔 인수인계 문서를 작업 폴더에 써두고, 사용량 한도가 리셋되는 시간에 맞춰 새 대화로 넘어가기로 했다.
새 대화에 붙여넣을 첫 메시지까지 만들어줬다.

```
집컴 I:\탄자니아_편집\인수인계.md 읽고 탄자니아 편집 이어서 하자.
권한 필요한 거 처음에 한 번에 다 받아가고, 작업은 병렬로.
```

인수인계 문서에는 이번에 배운 요령도 같이 들어갔다.

| 요령 | 내용 |
|---|---|
| 외장하드 읽기 | 느리다. 파일 전체를 읽지 말고 필요한 구간만 |
| 출력 | 결과는 요약만 받기. 로그가 쏟아지면 그게 다 비용 |
| 검증 | 오래 돌리기 전에 샘플 하나로 가설부터 확인 |
| 대량 복사 | 명령어 복사보다 7-Zip 파일관리자가 빠름 |
| 소리 싱크 | 두 영상의 소리 크기 변화를 비교해서 맞추기 |
